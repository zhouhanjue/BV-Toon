# BV-Toon 1.7.2

> MMD ワンクリック・トゥーン · 泛光（グロー）が全モデルで均一になりました ·
> 「添加泛光」は推測せず**実測**します · 測れないときは明示します
> （整合性チェック / 透かしの三状態 / 画面の破壊 / 強制署名は 1.7.1 とまったく同じ）

## インストール

1. `BV-Toon-1.7.2.zip`（リリース添付）をダウンロード
2. Blender：`編集 > プリファレンス > アドオン > v > ディスクからインストール`
3. **BV-Toon** を有効化 → MMD モデルを選択 → `N` → 「**Toon**」タブ → **ワンクリック・トゥーン**

Blender 4.5 以降と、オープンソースのアドオン
[mmd_tools](https://extensions.blender.org/add-ons/mmd-tools/) が必要です。

> **今回触ったのはグローだけです。** 1.7.1 の整合性チェック、透かしの三状態、画面の破壊、強制署名、
> そして「顔だけにチーク」の一連の処理は**一行も変えていません** —— 正常な出力にはこれまでどおり
> `渲染 BVToon / @BVan` の署名が入ります。マニフェストは zip に同梱済みで、ソースを**手作業でコピー**
> した副本は「未検証コピー」となり、戻す正しい手段は `python tools\install_bv_toon.py` の実行だけです。

## 症状：泛光が不均一で、暗いキャラクターはほとんど光らない

* 作者の報告そのまま：「泛光が不均一 —— 胡桃 などのキャラクターは 奥黛塔 より明らかに弱い。全キャラクターを 奥黛塔 の水準まで上げてほしい」
* 最も極端な言い方をすれば「**胡桃 にはグローがまったく無い**」で、その一方 奥黛塔 の光の輪は十分でした
* これは印象の問題ではなく**測定できます**：同一カメラ・同一設定で、シルエット外の明るさは **7 倍**違いました

## 根本原因：グローの経路全体が「絶対輝度」で動いている（640×853・同一カメラ・EEVEE 実測）

グローの光源はレンダリングの **Emit パス**（トゥーンシェーダ自体が全発光）で、そこに**しきい値 0.95 を超える
テクスチャ部品**、さらに「**外側グロー**」が加わります —— これは Emit の `max(RGB)` が **0.60 を超えた**
場所でしか点火しません。つまり**服が暗いほど光は少なくなる**、すべて絶対量で決まっていました：

| モデル | キャラクター平均輝度（グロー無し） | キャラクター上の増加 | シルエット外の輪の増加 |
|---|---|---|---|
| 奥黛塔（白い肌 / 白い服） | 0.735 | +0.0497 | +0.160 |
| 芙宁娜 | 0.586 | +0.0075 | +0.029 |
| 胡桃（暗い服） | 0.421 | +0.0060 | +0.017 |
| 初音ミク | 0.964 | +0.0099 | +0.271 |

奥黛塔 は 胡桃 より **7 倍**明るく光っていました ——「胡桃 にはグローがまったく無い」は決して誇張ではありません。

* **試して却下した方法**：最初の版はマテリアルの平均ベースカラー × `輝度` からモデルごとのゲインを推測しました。
  これは機能しません —— マテリアルの平均値は**画面のどれだけが明るいかを予測できない**からです：
  胡桃 では **1.44 倍**の増幅しか導けませんでしたが、実測では**およそ 9 倍**が必要でした。

## ハイライト：「添加泛光」は推測ではなく実測します

* 「添加泛光」はまず **192×192 を 2 フレーム**レンダリングし（グロー強度 0 と現在の強度）、そのうえで
  **「シルエットの外側の輪」**だけを見ます：グロー無しでは黒く、グロー有りでは点灯し、かつ**シルエットから 2 px 以内**のピクセル
* 見たら**閉ループ**にします：その輪が目標より暗ければ強度を掛けて**もう一度測ります**。最大 **3 回**
  （「グロー無し」のフレームは再利用するので、コストは **1 + N 枚の極小レンダリング**）
* **目標値 0.16** —— これは 奥黛塔 が、みんなが納得していた設定で測った値そのものです
* 自動値は **[0.03, 2.50]** にクランプされ、しかも**上げる方向のみ**：もともと目標より明るいキャラクター
  （初音ミク、0.271）は**そのまま据え置き**です —— 要件は「暗いキャラクターを暗いままにしない」であって
  「明るい方を暗くする」ではありません

| 段階 | 内容 |
|---|---|
| **測定フレーム** | 192×192 × 2（強度 0 / 現在の強度）。「グロー無し」は閉ループで再利用 |
| **測るピクセル** | グロー無しで黒、グロー有りで点灯、かつシルエットから **2 px** 以内のピクセル（「シルエットの外側の輪」） |
| **目標** | **0.16** |
| **閉ループ** | 目標より暗い ⇒ 強度を掛けて再測定、最大 **3 回** |
| **値** | **[0.03, 2.50]** にクランプ、**上げる方向のみ** |

## ハイライト：標定の口径（この数字でなければならない理由）

* 測定帯は**画面の固定比率**でなければなりません（192 px での 2 px ≈ 幅の **1%**）。**光のにじみ半径自体が
  画面のパーセンテージ**だからで、両者は一緒にスケールする必要があります
* 反例：**96 px** で **3 px** の帯を使うと、**シルエットに密着した明るい芯**を拾ってしまい、応答を過大評価します
  —— 胡桃 はそこで **0.265** を示しましたが、全解像度での真値は **0.166** でした
* 一度の測定では足りません：グローは **1.0** で**頭打ち**になります（奥黛塔 の単位強度あたりの応答は
  強度 0.10 で **1.49**、1.2 では **0.43** しかありません）。だから一回の線形外挿ではなく閉ループなのです

## その他の変更（1.7.2）

* **測定中はシーンを保護します**：長辺の解像度を一時的に **192 px** にし（アスペクトは維持）、レンダリングの
  スタンプを切り、さらに強制署名の `render_pre` ハンドラを**一時的に外します**（白いスタンプ文字が測定を汚すため）
  —— そして**必ず戻します**。監査は測定後にそのハンドラが**まだ装着されている**ことをアサートします
* レンダリング設定はすべて復元し、一時 PNG は一時ディレクトリに書いて**削除**します
* **測れないときは明示します**：シーンにカメラが無い、画面に何も収まっていない、見つかった輪のピクセルが
  **12 個未満**のいずれかの場合、アドオンはオペレータレポートで**はっきり伝え**（同時にシーンの
  `bv_glow_note` に保存）、旧来の既定強度 **0.10** を維持します —— **測ったふりはしません**
* グローグループに新しい入力 **`增益`**（gain、既定 **1.0**）：Emit ベースのグロー光源に掛かる手動倍率で、
  **外側グローのゲートより前**に適用されます —— これでゲートもモデル相対になります。**手で回すノブであり、自動設定はされません**
* 新しい検証ツール：`tools\check_glow_uniform.py`（モデルごとに 読み込み → ワンクリック・トゥーン → 添加泛光 →
  グロー無し/有りをレンダリングし、輪が **≥ 0.10 かつ ≤ 0.45** であること、強制署名ハンドラが測定を生き延びたこと、
  正規化した各モデルが**互いに 1.6 倍以内**であることをアサート。現在 `failures=0`）、プローブ
  `_scratch\probe_glow_models.py`、そして `tools\audit_bv_toon.py` の**新しいグロー検査 6 項目**
  （現在 **70 通過 / 既知の偽失敗 2 件** —— `remove_glow` と `set_eye_shadow` が CANCELLED を返すのは正常です）
* 比較画像：`_glow_demo\` に、モデルごとに `<name>-0-noglow.png` / `<name>-1-glow.png` の組で出力されます

## 実測と検証の再現

条件：**同一カメラ**、両方とも**自動強度**でレンダリング。

| モデル | 修正前の輪 | 修正後の輪 | キャラクター上（前 → 後） |
|---|---|---|---|
| 奥黛塔 | 0.160 | **0.152** | — |
| 胡桃 | 0.017 | **0.144** | **+0.0060 → +0.083** |
| 芙宁娜 | 0.029 | **0.142** | **+0.0075 → +0.061** |
| 初音ミク | 0.271 | **0.271**（上げる方向のみ、据え置き） | — |

* 奥黛塔 / 胡桃 / 芙宁娜 の輪は**互いに 1.07 倍以内**になりました（修正前は **7 倍**）。初音ミク は
  上げる方向のみの規則により **0.271 のまま据え置き**です

```
& 'C:\Program Files\XF Blender 4.5\blender.exe' -b --factory-startup --python tools\check_glow_uniform.py -- dist\BV-Toon-1.7.2.zip _glow_demo <模型.pmx 或 .pmd …>
python tools\package_bv_toon.py --verify
```

1 行目がモデルごとの測定全体を回し（ペア画像とアサート結果は `_glow_demo\` に出力されます）、
2 行目が zip に同梱したマニフェストを照合します。

## ツールの落とし穴：測定は強制署名ハンドラを一時的に外します（必ず戻します）

* 測定は**スタンプ文字の無い**画面で行う必要があるため、測定中は強制署名の `render_pre` ハンドラを
  **一時的に外します**
* リスクは現実的です：もし戻し忘れれば、**以降のすべてのレンダリングから `渲染 BVToon / @BVan` の署名が
  黙って消え**、しかもどこにもエラーが出ません
* そのため**必ず戻し**、さらに `tools\audit_bv_toon.py` が**測定後もハンドラが装着されていることをアサート**します

## アップグレードと互換性（1.7.1 → 1.7.2）

* グローのノードグループに**入力が一つ増えた**ので ⇒ アップグレード後は**グローを削除してから追加し直して**ください
  （あるいは「添加泛光」をもう一度押すだけです —— 内部的に削除してから追加します）
* 強度は**現在のカメラ / ポーズから測る**値です ⇒ カメラやモデルを変えた後、測り直したいときは
  「添加泛光」をもう一度押してください
* zip は `dist\BV-Toon-1.7.2.zip`、インストールは `編集 > プリファレンス > アドオン > ディスクからインストール`。
  Blender 4.5 以降と mmd_tools が必要です
* マニフェストは**zip に同梱**されています。ソースから**手作業で**インストールした副本は「未検証コピー」の透かしが出ます。
  正常に戻す唯一の公式な手段は `python tools\install_bv_toon.py` の実行です

## 未実装

* 目標値 **0.16** は**一つの参照モデル**（奥黛塔）の**既定設定**で標定したもので、別の設定では外れる可能性があります
* 自動強度は**シーン単位**の値です（コンポジタのグローグループノード上にあります）：明るさが大きく違うキャラクターを
  同じシーンに複数置くと、**カメラに映る画面全体**として測られます —— キャラクターごとの値が必要なら
  **シーンを分けて**ください
* 1.7.1 に挙げた項目（マテリアル名の特殊処理、サブテクスチャのハイライト、顔認識の対応範囲）は本版とは無関係で、未実装のままです
