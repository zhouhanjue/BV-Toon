# BV-Toon

[中文](README.md) ｜ [English](README.en.md) ｜ **日本語**

> MMD モデルのワンクリック・トゥーン · マテリアルのネイティブ読み込み · エッジプレビュー · 目影 · チーク · ブルーム · 署名の強制

**現在のバージョン：1.7.2**

**BV-Toon は独自に開発した Blender アドオンです**：コード・ノードグラフ・アセットはすべて自作で、サードパーティ製アドオンのコードやアセットは一切含みません。
シェーディングノードは同梱の `BVToonData/BVToonShading.blend` に組み立てられており、Blender で直接開いて手で編集できます。このアセットが無い場合は自動的にその場での生成にフォールバックします。

> 設計にあたっては MMD トゥーンシェーディングの一般的な手法を参考にし、同種の Blender アドオンの公開された挙動から着想を得ています。動作にはオープンソースのアドオン [mmd_tools](https://extensions.blender.org/add-ons/mmd-tools/) が必要です。本プロジェクトは、いかなるサードパーティ製アドオンともコード上・アセット上の関係はありません。

## できること

| 機能 | 説明 |
|---|---|
| **ワンクリック・トゥーン（一键卡渲）** | ボタンひとつ：トゥーンプリセットを適用 → MMD エッジプレビューを生成 |
| **マテリアルのネイティブ読み込み（原生读取材质）** | mmd_tools の `mmd_material`（基色 / 球面 / サブテクスチャ / 透明度）を直接読み込み、**破壊的な変換は行いません**。球面レイヤーのスパンコールや光沢も失われません |
| **トゥーンプリセット（卡渲预设）** | 一键卡渲 / 冷调 / 夜色暖。パラメータは `bv_shading.py` にあるあの表そのもので、自由に変更できます |
| **ブルーム（泛光）** | コンポジタ効果：**自発光（Emit）駆動 + シルエット外の発光**。ライトが無くても効果があり、明るい背景も一緒にボケたりしません。**強度はモデルごとに実測して自動決定**（暗い色のキャラクターが他より暗くなることはありません）。ワンクリックで取り外し可能 |
| **チーク / 目影（腮红 / 目影）** | チークは**顔にだけ**追加します：まず顔のマテリアルを認識し、次に**モデル内蔵のチークテクスチャ（`照れ` など）をマスクとして優先使用**（作者が描いた形）。無ければ**幾何学的な頬サークル**（`腮红保底` + `脸颊圈`、明暗は見ません）にフォールバックします。目影は「目影」マテリアルを半透明の黒にします |
| **署名の強制（强制署名水印）** | レンダリング前に `渲染 BVToon / @BVan` を強制的に焼き込みます（85% 透明・背景枠なし）。改変されたコピーは「未授权修改版」になります。ハンドラは `persistent` 付きで、有効化のたび／パネル描画のたびに付け直されます —— つまり新規作成やファイルを開いた後でも**強制されます** |
| **マテリアルツリーをきれいに保つ（材质树保持干净）** | トゥーンが引き継いだ後、マテリアルツリー内の非トゥーンノードは整理され、`bv_*` と出力だけが残ります（二つのノード構成が喧嘩しないように）。mmd_tools の `mmd_material` データ自体は書き換えませんが、**「基本マテリアルにワンクリックで戻す」ボタンはありません** |

## 整合性チェック（ハッシュによる改変検出）

パッケージング時に `BVToonData/integrity.json` を生成します（トップレベルの `.py` 7 個 + トゥーンアセットの SHA-256）。zip と一緒に配布されます。
アドオンは**読み込み時**、**パネルを描画するたび**、**レンダリングの直前**に毎回照合します：

| 状態 | いつ | 透かし |
|---|---|---|
| 正常 | マニフェストがあり、ファイルがすべて一致する | `渲染 BVToon / @BVan`（85% 透明の白文字、パネルで変更可） |
| 未授权修改版 | マニフェストはあるが、ファイルが改変 / 欠落 / 余分 | `未授权修改版 / UNAUTHORIZED MODIFIED COPY`（不透明の赤文字 + 黒背景） |
| 未验证副本 | マニフェストが無い、またはマニフェストが読めない | `未验证副本 / UNVERIFIED COPY`（不透明の赤文字 + 黒背景） |

### 検証に通らない場合：画面は必ず破壊されます（選べる段階はありません）

**スイッチもドロップダウンもありません** —— パネルには一行の説明があるだけです：`损毁：被改或未验证都损毁（唯一档位，无选项）`。
ルールはただ一つです：

* 検証**通過** → 画面はいつもどおり
* 検証**不通過**（改変 / 未検証）→ 画面は**ピクセル化 + レベル圧縮 + 彩度を落として暗く**され、一目で失敗作と分かります

破壊はコンポジタ（`bv_damage.py`）を通すので、静止画・アニメーション・ビューポートレンダリングの**すべて**に効きます。正常に戻す（マニフェストを再計算する）と
ノードは外され、配線も元に戻り、ゴミは残りません。

* **なぜ選択肢が無いのか**：改変されたコピーが使える絵を出せてしまうべきではないからです。緩める余地は残しません
* **代償（正直に言えば）**：「未検証」も不通過として扱うため、**ソースディレクトリから `addons` にそのままコピーした副本
  （マニフェストが無い）も破壊されます**。正常に戻る正しい道は一つだけ：`tools/install_bv_toon.py` を一度実行してマニフェストを再計算することです
* **これは暗号化ではなく、そのつもりもありません**：知識のある人はマニフェストごと再計算できますし、アドオンを無効化することもできます。
  ここで防いでいるのは「少し名前を変えて自分が書いたと言う」ことと、改変されたコピーが**自力で使える絵を出せない**ようにすることです。
* **ライセンスとの関係**：GPL v3 は改変と再配布を認めています —— ここで触っているのは**そのコピー自身がレンダリングする画面**だけで、
  誰かのコード改変・再配布・商用利用を制限するものではありません。LICENSE §7 の追加条項 2 はもともと「改変版は元のバージョンと
  異なることを合理的な方法で明示しなければならない」と定めており、透かしと破壊はどちらもその要求の実装です。
* マニフェストの対象はトップレベルの `*.py` と `BVToonData/BVToonShading.blend` です。ドキュメントと `LICENSE` は対象外です。

## チーク（顔だけに）

「チークを追加（顔だけ）」（添加腮红（只给脸））をクリックすると：

1. **「顔」を認識する**：マテリアル名の `颜/顔/脸/face/フェイス…` → メッシュ名 → ベースカラーテクスチャ名（一意）→
   頭部のジオメトリ（MMD 標準ボーン `頭`/`首` で区切られる範囲で最も面積が大きい部分）→ 唯一の肌色マテリアル（`肌/skin`）。
   どれにも当たらなければ**警告 + マテリアル名の一覧**を出します。決して推測せず、「とりあえず全部に付ける」ことも決してしません。**ジオメトリまで推測**で、
   なおかつ推測したマテリアルの**面数 < 128**（大半は目や口などのパーツ）のときは、パネルに赤文字が出るので「顔＝現在のマテリアル」（脸=当前材质）で自分で指定してください
2. **モデル内蔵のチークテクスチャ（`照れ` / `blush` / `チーク`…）をマスクとして優先** —— それは作者自身が描いたチークの形です。
   ただしこの種のテクスチャは**alpha で模様を描いている**点に注意（実測：`照れ.png` は 2048²、98% が完全透明、RGB はほぼ一様な淡いピンクなので、
   輝度をマスクにしても全く役に立ちません）。そこでアドオンはこれをトゥーングループの **`腮红贴图`** 入力に接続し、
   `Map Range` で淡い alpha を明確なマスクに整えます（0.15 以下は無し、0.50 以上は最大）
3. モデルにこの種のテクスチャが無い → **レンダラー内蔵のチークマスク**にフォールバック：`腮红保底 + (1 − 腮红保底) × 脸颊圈`。
   **明暗は見ず、ジオメトリだけを見ます** —— 以前「輝度しきい値」で作った二つの版（絶対輝度・相対輝度）は、複数のモデルで
   実測すると常に 0 で、顔にチークがまったく出ませんでした。現在は顔マテリアル全体に必ず `腮红保底`（既定 0.35）の濃さが乗り、
   両頬は**脸颊圈**で最大まで濃くなります（球の中心は顔マテリアルの実頂点に吸着、半径 = 顔の半幅の 42%）
4. それ以外のマテリアルのチークは一律**ゼロ**にします。認識結果と使った仕組みはパネルに表示されます
   （`脸材质：颜` / `腮红：着色器腮红，位置=脸颊（…）`）

モデル横断の検収（9 モデル、640×853、同一カメラ、ピクセル単位で「変化は頭部だけ」と断言）：
初音ミク 661 / MEIKO 5547 / 巡音ルカ 1775 / 胡桃 1203 / 芙宁娜 549 / 雷电 444 / 沃雅妮莎 633 /
蕾米埃尔 200 ピクセル。`照れ` テクスチャを内蔵するモデルは 2 の経路（作者が描いた形）を通ります。たとえば 奥黛塔 は
「はっきりした頬の赤い 2 点」（192 ピクセル・8 行にまたがる）であり、「顔全体のほてり」（2096 ピクセル・63 行にまたがる）ではありません。

パネルのモードが `替换单个【材质】` のときは、現在アクティブなマテリアルスロットを使います（顔を認識できないモデル用の手動の入口です）。

## ブルーム（強度はモデルごとに実測、キャラクターの明暗によらない）

ブルームのチェーン全体が扱うのは**絶対輝度**です（ソースはレンダリングの Emit チャンネル + 画面のしきい値を超えた部分で、外側の発光にはさらに
「自発光 > しきい値」のゲートがあります）。そのため暗い色のキャラクターは明るいキャラクターよりどうしても少なくなります —— 同じパラメータで実測すると、
奥黛塔 のシルエット外の光は **+0.160**、胡桃 は **+0.017** だけ（7 倍の差で、見た目は「胡桃 にブルームが無い」）。

そこで「ブルームを追加」（添加泛光）をクリックすると**まず測ってから決めます**：

1. **192×192** の小さい画像を 2 枚レンダリングし（強度 0 / 現在値）、**シルエット外の光**がどれだけ明るくなったかを見ます
   （「オフなら黒、オンでだけ明るく、かつシルエットから 2 ピクセル以内」のピクセルを平均）
2. 足りなければ比例して上げ、**閉ループ**で最大 3 回やり直し、目標 **0.16**（= 奥黛塔 を誰もが納得する
   設定で測った値）に近づけます。自動値は `[0.03, 2.50]` にクランプ
3. **上にしか調整しません**：もともと 0.16 より明るいキャラクターはそのまま（明るいものを暗くしません）
4. 測れない場合（カメラが無い / カメラが収めていない / シルエット外が 12 ピクセル未満）は**報告に正直に書きます**。
   強度は既定の `0.10` のままで、測ったふりはしません

実測結果：シルエット外の光は 奥黛塔 **0.152** / 胡桃 **0.144** / 芙宁娜 **0.142**（差は 1.07 倍）。

コンポジタ内の `BVToon_Glow` グループノードはいつでも手で調整できます：**強度 / しきい値 / サイズ / 外側の発光 / ゲイン**。
`增益`（ゲイン）は手動微調整用の乗数です（自発光の枝に掛かり、外側発光のゲートより前に位置します —— つまり「どれだけ明るければ
明部か」もこのモデル相対になります）。

> 測っているのは**現在のカメラが見ている画面**です：カメラ位置やモデルを変えて測り直したいときは、もう一度「ブルームを追加」（添加泛光）を押してください。

## 依存関係

- **Blender 4.5 以降**（ブルームは Eevee Next の Emit チャンネルを使用。3.6+ でも動作しますがブルームは制限されます）
- **[mmd_tools](https://extensions.blender.org/add-ons/mmd-tools/)**（オープンソースの MMD インポーター）——
  MMD マテリアルの読み込み、モデルのインポート、エッジプレビューに必要です

他に必要なアドオンはありません。

## インストール

1. `編集 > プリファレンス > アドオン > 右上の v > ディスクからインストール` → `BV-Toon-1.7.2.zip` を選択
2. 一覧で **BV-Toon** にチェックを入れる
3. MMD モデルを選択 → `N` → 「Toon」タブ → **ワンクリック・トゥーン（一键卡渲）**

ソースディレクトリから手でコピーしてインストールしても構いませんが、その場合は整合性マニフェストが無いため、透かしは「未验证副本」と表示されます ——
正常な署名が欲しい場合は Release の zip を使ってください。あるいはコピー先のディレクトリで自分で一度
`python tools/install_bv_toon.py --target <そのディレクトリ>` を実行してください。

## ディレクトリ構成

| ファイル | 役割 |
|---|---|
| `__init__.py` | bl_info、パネル、オペレーター、レンダリング前の透かし強制 |
| `bv_util.py` | mmd_tools の MMD マテリアルデータの読み込み、UV グループの自作、球面 / サブテクスチャレイヤー |
| `bv_shading.py` | トゥーンノードグループ（Python でその場生成）+ プリセット表 |
| `bv_materials.py` | 適用 / ノードの整理 / チーク / 目影 / 輪郭線 / 環境色 |
| `bv_glow.py` | ブルーム（自発光駆動 + シルエット外の発光 + モデルごとに実測した自動強度） |
| `bv_integrity.py` | 整合性チェック（ハッシュマニフェストの生成と照合、三態判定） |
| `BVToonData/BVToonShading.blend` | トゥーンノードグループのアセット（75 ノード / 31 インターフェース、手で編集可） |
| `BVToonData/integrity.json` | パッケージング / インストール時に生成されるハッシュマニフェスト（手書きではありません） |
